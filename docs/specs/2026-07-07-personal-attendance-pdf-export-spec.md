## 1. Problem

Android needs official backend-generated Personal Attendance PDF report for the authenticated user's My Attendance Report screen.

The backend is the source of truth for attendance/reporting outcomes. Android must request, preview, download, and share the PDF, but must not calculate official totals or render the official PDF locally.

## 2. PM Contract Decision

Superseded endpoints:

- `GET /api/attendance/report/personal/pdf`
- `GET /api/attendance/report/export.pdf?period=monthly`

Final namespace:

- Preview: `GET /api/attendance/history/personal/pdf`
- Download/export: `GET /api/attendance/history/export.pdf?period=monthly`

## 3. Endpoint Contract

### 3.1 Preview endpoint

```http
GET /api/attendance/history/personal/pdf
Authorization: Bearer <token>
```

Purpose: Android in-app PDF preview for the authenticated user's personal attendance report.

Expected headers:

```http
200 OK
Content-Type: application/pdf
Content-Disposition: inline; filename="infinite-track-attendance-report-YYYY-MM.pdf"
Cache-Control: no-store
```

### 3.2 Download/export endpoint

```http
GET /api/attendance/history/export.pdf?period=monthly
Authorization: Bearer <token>
```

Purpose: Android download/share/export PDF for the authenticated user's personal attendance report.

Expected headers:

```http
200 OK
Content-Type: application/pdf
Content-Disposition: attachment; filename="infinite-track-attendance-report-YYYY-MM.pdf"
Cache-Control: no-store
```

## 4. Query Contract

Supported query params:

```text
period=daily|weekly|monthly|custom
start_date=YYYY-MM-DD [required for custom]
end_date=YYYY-MM-DD [required for custom]
timezone=Asia/Makassar [optional]
```

Default when query is empty:

```text
period=monthly
current month
authenticated user only
```

MVP required:

```http
GET /api/attendance/history/personal/pdf?period=monthly
GET /api/attendance/history/export.pdf?period=monthly
```

Custom range is included in the target implementation only if it can safely reuse existing strict date validation and tests.

## 5. Security and Scope

Required:

- User scope must come from `req.user.id`.
- Normal Android clients must not be able to request arbitrary `user_id`.
- Query/body `user_id` must be ignored or rejected for this personal Android contract.
- PDF must contain data for exactly one authenticated user.
- PDF must not expose other users' names, NIP/NIM, records, statuses, work modes, scores, or locations.
- Admin/Management export for another user is out of scope.
- Existing admin/management summary export behavior must not be reused as Android personal behavior.

## 6. Shared Service Rule

Both endpoints must use the same backend report payload/calculation service.

Only response header difference is allowed:

- Preview: `Content-Disposition: inline`
- Download/export: `Content-Disposition: attachment`

No drift allowed for:

- report summary
- total work hours
- late/alpha counters
- attendance mode distribution
- attendance timeline
- empty-period behavior

## 7. PDF Content Scope

Adopted:

- My Attendance Report PDF
- Report Summary
- Attendance Mode Distribution
- Attendance Timeline
- Period metadata
- Generated-at metadata

Not adopted:

- Personal Insight
- Smart Reminder
- Company Services
- AI-generated interpretation
- Admin multi-user export

## 8. PDF Content Requirements

Header:

- Infinite Track
- My Attendance Report
- User full name
- Role / position if available
- Period label
- Generated at

Report Summary:

- Attendance Rate only if denominator is verified
- Total Work Hours
- Late
- Alpha
- Attended Days
- Expected Working Days if available

Attendance Mode Distribution:

- WFO
- WFA
- WFH only if verified by category mapping / INF-164

Attendance Timeline:

- Date
- Mode
- Check-in
- Check-out
- Work Hour
- Status
- Location if available

Footer:

- Generated by Infinite Track
- Backend source-of-truth notice
- Generated timestamp

## 9. Data Sources

Use existing backend data only:

- `attendance`
- `attendance_categories`
- `attendance_statuses`
- `locations`
- `users`
- `roles`
- `positions`

No new table for MVP.

Do not create:

- report cache table
- `report_exports` table
- dashboard/admin export table

## 10. Calculation Rules

Required:

- `total_work_hours` calculated from backend attendance data.
- Late, alpha, and status counters mapped from backend attendance status IDs/names.
- WFO/WFA/WFH counts mapped from backend attendance category IDs/names.
- WFH must be omitted or marked Needs Verification unless INF-164 mapping is verified.
- Do not fabricate `attendance_rate_percent`.
- Attendance rate only appears when denominator is verified.
- If denominator is unavailable, render attendance rate as unavailable with explanation.
- Do not include Personal Insight.
- Do not include Smart Reminder.
- Do not include Company Services.
- Do not include AI-generated interpretation.

Alpha/absent safety:

- Alpha/absent rows must not show misleading `work_hour`.
- If `time_in`, `time_out`, or `work_hour` is invalid for an alpha row, render safe display:
  - `time_range: "--:-- - --:--"`
  - `work_hour: "—"` or unavailable
  - `work_hour_raw: null`

## 11. Empty Period Behavior

For a valid period with no attendance rows, return a valid PDF, not a server error.

Empty-state text:

```text
No attendance records are available for this period.
```

## 13. Proposed Architecture

```text
AttendanceReportController additions
├── previewMyAttendanceReportPdf()
└── exportMyAttendanceReportPdf()

AttendanceReportService
├── buildPeriod()
├── buildSummary()
├── buildModeDistribution()
├── buildTimeline()
└── buildReportPayload()

PdfReportRenderer
└── renderMyAttendanceReportPdf(payload)
```

Rules:

- PDF renderer receives normalized payload.
- PDF renderer never queries database.
- Both endpoints share service and renderer.
- Controller only handles request user scope, headers, and error response.
