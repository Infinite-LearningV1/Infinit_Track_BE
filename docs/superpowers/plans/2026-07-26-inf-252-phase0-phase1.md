# INF-252 Phase 0 + Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lay the documentation, lint, error, and integration-test foundations for the Modular MVC migration without changing a single byte of observable API behavior.

**Architecture:** Phase 0a publishes the architecture documents that define the migration's scope. Phase 1 adds a typed-error taxonomy and a pure error-to-HTTP translator, wired into the existing global error handler as an additive branch so legacy behavior is untouched. Phase 0c adds a real MySQL service to CI, because the current suite mocks Sequelize and therefore cannot detect SQL regressions once queries move into repositories.

**Tech Stack:** Node.js ESM, Express 4, Sequelize 6, Jest 29 (`--experimental-vm-modules`), supertest 7, ESLint 8 (`.eslintrc.cjs`, legacy eslintrc format — **not** flat config), MySQL 8.

**Spec:** `docs/superpowers/specs/2026-07-26-inf-252-modular-mvc-design.md`
**ADR:** `docs/adr/ADR-009-modular-mvc-per-feature.md`

## Global Constraints

- No observable API behavior may change. No route added, removed, or renamed. No response envelope altered.
- `npm test` must stay green at every commit. Baseline is **90 suites / 579 tests**, measured at `5ce2f69`.
- `npm run lint` must be clean at every commit.
- ESLint is **v8 with `.eslintrc.cjs`**. Use the `overrides` array. Flat-config syntax (`eslint.config.js`) will not be read.
- Tests are ESM. Mock modules with `jest.unstable_mockModule(...)` **before** `await import(...)`. This ordering is mandatory — a static `import` of the module under test defeats the mock.
- `src/middlewares/errorHandler.js` keeps its existing branches byte for byte. Only one new branch may be added, and only ahead of the legacy branches.
- ESLint layer rules apply to `src/modules/**` only. Legacy folders must remain lint-clean without modification.
- Database migrations are manual-first. Do not run `npm run migrate` against any non-test database.
- Timezone for all business logic is Asia/Jakarta (UTC+7). Do not introduce UTC assumptions.
- In a fresh worktree, install with `PUPPETEER_SKIP_DOWNLOAD=true npm install` if the puppeteer postinstall fails on a corrupt browser cache.

## Scope note

**Phase 0b — the characterization backfill for the 37 priority endpoints — is deliberately not planned here.** Its scope is defined by the test-coverage column produced by Task 1. Writing concrete test code for those endpoints before that column exists would be guesswork. Phase 0b gets its own plan, derived from `docs/architecture/api-contract-inventory.md`, once Task 1 merges.

Task ordering — **Tasks 2–6 are not all independent**:

```text
Task 1 (docs) ── blocks everything
      ├── Task 2 (eslint)        independent
      ├── Task 7 (CI harness)    independent
      └── Task 3 (AppError)
            └── Task 4 (toErrorResponse)   consumes AppError
                  └── Task 6 (wire branch) consumes Tasks 3, 4 and 5
            Task 5 (characterization)  independent of 3 and 4,
                                       but must land before Task 6
```

Task 6 must not start before Tasks 3, 4 and 5 have all landed — its whole purpose is to be provably inert against the characterization Task 5 adds. The per-task **Interfaces** blocks state these dependencies precisely; this graph summarizes them.

```javascript
export class AppError extends Error {
  constructor(message, { code, status, details } = {}) {
    super(message);
    this.name = new.target.name;
    this.code = code;
    this.status = status;

    if (details !== undefined) {
      this.details = details;
    }

    if (Error.captureStackTrace) {
      Error.captureStackTrace(this, new.target);
    }
  }
}

export class ValidationError extends AppError {
  constructor(message, details) {
    super(message, { code: 'E_VALIDATION', status: 400, details });
  }
}

export class UnauthorizedError extends AppError {
  constructor(message, details) {
    super(message, { code: 'E_UNAUTHORIZED', status: 401, details });
  }
}

export class ForbiddenError extends AppError {
  constructor(message, details) {
    super(message, { code: 'E_FORBIDDEN', status: 403, details });
  }
}

export class NotFoundError extends AppError {
  constructor(message, details) {
    super(message, { code: 'E_NOT_FOUND', status: 404, details });
  }
}

export class ConflictError extends AppError {
  constructor(message, details) {
    super(message, { code: 'E_CONFLICT', status: 409, details });
  }
}

const MASKED_MESSAGE = 'Internal server error';

export const toErrorResponse = (err, { env } = {}) => {
  const status = err.status || 500;
  const shouldMask = status >= 500 && env === 'production';

  const body = {
    success: false,
    message: shouldMask ? MASKED_MESSAGE : err.message
  };

  if (err.code) {
    body.code = err.code;
  }

  if (err.details !== undefined) {
    body.details = err.details;
  }

  return { status, body };
};
```

  TEST_DB_USER = 'root',
  TEST_DB_PASS = 'root',
  TEST_DB_NAME = 'infinite_track_test'

    timezone: '+07:00',
    logging: false

  await sequelize.authenticate();
});

afterAll(async () => {
  await sequelize.close();
});

describe('users list query against real MySQL', () => {
  it('connects to the migrated test schema', async () => {
    const [rows] = await sequelize.query('SELECT DATABASE() AS db');
    expect(rows[0].db).toBe(TEST_DB_NAME);
